## 1. Project Overview

Banks and payment processors handle millions of financial transactions continuously, a fraction of which are fraudulent. This project implements an enterprise-grade, real-time **Distributed Fraud Monitoring System** that streams incoming payments, scores each transaction against multiple temporal fraud rules, makes automated decisions (`APPROVE`, `REVIEW`, `BLOCK`), records audit trails in an **Apache Iceberg Lakehouse** on HDFS, and serves operational analytics through an interactive **Streamlit Dashboard**.

The pipeline is stress-tested under **Chaos Engineering** scenarios (killing workers, killing the Spark master, and injecting disordered/late arrivals) to empirically demonstrate state-store recovery, deduplication, and zero data loss.

## 2. Tech Stack & Architecture

- **Message Broker:** Apache Kafka (streaming transaction events)
- **Stream Processing:** Apache Spark Structured Streaming (PySpark)
- **Storage Layer:** HDFS (Single-Node storage & checkpointing)
- **Lakehouse Table Format:** Apache Iceberg
- **Query Engine:** Spark SQL
- **Operational Dashboard:** Streamlit
- **Validation Engine:** Automated Python/Spark Ground-Truth Verifier

### 4-Node Distributed VM Topology

| Node / VM | Component | Role |
|---|---|---|
| **VM 1** | Kafka Producer & Broker | Streams live payments from `transactions.csv` |
| **VM 2** | Spark Master & Driver | Coordinates Structured Streaming execution |
| **VM 3** | HDFS + Iceberg + Verifier | Hosts Iceberg tables, checkpoints, and verifier engine |
| **VM 4** | Spark Worker + Streamlit | Serves real-time investigation UI and charts |

## 3. Fraud Detection Rules

The engine evaluates transactions using event-time sliding windows (**2-minute window sliding every 30 seconds**) with a **1-minute watermark** for late arrivals:

- **Rule 1 (High Amount):** Any single payment $\ge$ ₹50,000.
- **Rule 2 (Velocity Burst):** $\ge$ 5 payments from the same account within a 2-minute window.
- **Rule 3 (Cumulative Total):** $\ge$ 2 payments from the same account totaling > ₹6,00,000 within a 2-minute window.
- **Rule 4 (Destination Spam):** $\ge$ 3 payments from the same account to the *same destination* within a 2-minute window.
- **Rule 5 (Decision Matrix):**
  - $\ge$ 2 rules active $\rightarrow$ **`BLOCK`**
  - 1 rule active $\rightarrow$ **`REVIEW`**
  - 0 rules active $\rightarrow$ **`APPROVE`**
